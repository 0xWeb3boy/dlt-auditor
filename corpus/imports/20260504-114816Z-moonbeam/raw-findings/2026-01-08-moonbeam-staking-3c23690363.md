Evidence supports an accounting inconsistency that could corrupt the reward snapshot denominator and potentially overmint staking payout, but the provided material does not establish full exploitability, profit conditions, or impact outside the staking payout path.

## Before/After Behavior

Before the patch, decrease-request validation checked the current decrease against the bonded amount in isolation, and snapshot construction added the full pending decrease amount to `uncounted_stake` even when that amount could exceed the actual bond. After the patch, existing pending decreases are considered cumulatively for the `MinDelegation` constraint, and snapshot accounting caps the excluded amount at `bond.amount`.

# Root Cause

Multiple pending `DelegationAction::Decrease` requests for the same collator-delegator pair were not consistently bounded against the actual bonded stake across validation and reward snapshot accounting.

## Walkthrough

1. A delegator could schedule decrease requests for a collator-delegator pair.

2. The old validation path considered the current decrease request without proving that all pending decreases together still respected `MinDelegation`.

3. Reward snapshot construction then used pending decrease amounts when computing `uncounted_stake`.

4. The old snapshot code added the full decrease amount to `uncounted_stake` and subtracted it from `bond.amount`.

5. If pending decreases were stacked or aggregated beyond the actual bond, derived snapshot accounting could exceed real removable stake.

6. The patch sums pending decrease requests during validation and caps snapshot exclusion with `min(*amount, bond.amount)`.

7. The added regression test name explicitly ties the scenario to broken snapshot denominators or overminted payout.

# Fix Pattern

Validate cumulative pending state and cap derived accounting by the actual source balance before using it in reward calculations.

## How It Was Fixed

`delegation_requests.rs` computes the total pending decrease amount from scheduled requests and applies the minimum delegation check cumulatively. `lib.rs` caps pending decrease accounting at the current bond amount before updating `uncounted_stake` and rewardable bond amount. `tests.rs` adds a regression test for stacked decrease requests breaking the snapshot denominator or overminting payout.

# Why It Matters

1. Protects staking reward accounting integrity.

2. Prevents `uncounted_stake` from exceeding actual bonded stake.

3. Reduces risk of payout denominator corruption.

4. Evidence does not support claims of access-control bypass, consensus compromise, or arbitrary minting outside staking payouts.
