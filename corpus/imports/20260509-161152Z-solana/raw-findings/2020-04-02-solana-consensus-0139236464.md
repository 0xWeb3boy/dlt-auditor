# Summary

The patch changes Solana `ReplayStage` fork-voting logic so `switch_threshold` is computed with `tower.check_switch_threshold(...)`, failure is recorded explicitly, and the final vote predicate requires `switch_threshold`. This is consensus-relevant logic, but the supplied evidence does not prove a security vulnerability, exploit path, network split, or finalized consensus divergence. Treat as unclear rather than a confirmed or likely security fix.

## Before/After Behavior

Before the patch, the shown fork-selection code special-cased a selected bank whose ancestors contained `earliest_vote_on_fork` and selected `votable_bank_on_same_fork` without the shown `tower.check_switch_threshold(...)` call. The vote path also tracked `voted_on_different_fork` and later updated `earliest_vote_on_fork` and cleared `switch_threshold` after voting on a different fork. The shown final vote condition required lockout, vote threshold, and propagation confirmation, but not `switch_threshold`. After the patch, the heaviest-bank path computes `switch_threshold` through `tower.check_switch_threshold(...)`, records `FailedSwitchThreshold` when false, and requires `switch_threshold` in the final vote predicate.

# Root Cause

The grounded issue is inconsistent or under-enforced switch-threshold handling in the shown `ReplayStage` voting path. The evidence supports that the final vote decision previously did not include `switch_threshold`; it does not establish the concrete protocol impact of that omission.

## Walkthrough

1. `ReplayStage` evaluates a `heaviest_bank` during fork selection.

2. The removed code computed `selected_same_fork` by checking whether the selected bank's ancestors contained `earliest_vote_on_fork`.

3. When that condition was true, the removed code selected `votable_bank_on_same_fork` directly, with comments saying the switch threshold did not need to be checked.

4. The vote loop previously tracked `voted_on_different_fork` and later used it to update `earliest_vote_on_fork` and clear `switch_threshold`.

5. The patched code computes `switch_threshold` with `tower.check_switch_threshold(...)` in the shown heaviest-bank path.

6. The patched code adds `HeaviestForkFailures::FailedSwitchThreshold(bank.slot())` when the check fails.

7. The final vote condition now includes `switch_threshold` alongside lockout, vote threshold, and propagation confirmation.

# Fix Pattern

Compute the switch-threshold decision before voting, surface threshold failure in fork-selection diagnostics, and include the threshold result in the final vote predicate.

## How It Was Fixed

The patch removed the shown same-fork shortcut and `voted_on_different_fork` bookkeeping, added explicit `tower.check_switch_threshold(...)` handling, added `FailedSwitchThreshold` to failure reasons, and changed the vote condition to require `switch_threshold`.
