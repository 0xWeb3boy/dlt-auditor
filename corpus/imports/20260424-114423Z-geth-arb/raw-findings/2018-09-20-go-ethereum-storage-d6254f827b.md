# Summary

The patch changes go-ethereum core blockchain reorg tie-breaking. Before, equal-total-difficulty, same-height competing blocks could trigger a random reorg. After, the code is documented as preferentially keeping a locally mined canonical block, using a new `isLocalFn` callback threaded into `BlockChain` and `NewBlockChain`. This is plausibly security-adjacent because it touches fork-choice behavior and sits near a comment about selfish-mining resistance, but the provided evidence does not prove a concrete vulnerability, exploit path, consensus validation bypass, or state corruption.

## Before/After Behavior

Before the patch, `WriteBlockWithState` used block number first and then `mrand.Float64() < 0.5` to decide same-height equal-total-difficulty reorgs. After the patch, lower-number competing blocks can still cause reorg, but same-height equal-TD decisions enter logic documented as preferring locally mined blocks as canonical. `BlockChain` gains `isLocalFn func(common.Address) bool`, `NewBlockChain` accepts that callback, and call sites without local-author handling pass `nil`. Clique is explicitly excluded from the self-reorg-preserving path because the code comment warns it may introduce a deadlock.

# Root Cause

The prior local fork-choice policy used random selection for same-height equal-total-difficulty competitors. That could replace a locally authored canonical block without considering local miner ownership. The evidence supports this as an undesirable fork-choice behavior; it does not establish state corruption or a proven security exploit.
