# Summary

The supported finding is limited to error-handling hardening in the beacon engine's sync canonicalization path. Before the patch, two call sites invoked try_make_sync_target_canonical(...) and ignored its Result. After the patch, one path escalates fatal canonicalization errors to an internal engine error and the other logs unexpected failures. The diff shows improved handling of canonicalization failures, but it does not establish a concrete security vulnerability or prove that invalid state was previously accepted as canonical.

## Before/After Behavior

Before the patch, on_new_payload(...) and on_downloaded_block(...) called try_make_sync_target_canonical(...) and continued without checking the return value. After the patch, on_new_payload(...) inspects the Result and returns an internal error for fatal canonical errors, while on_downloaded_block(...) inspects the Result and logs unexpected failures instead of dropping them silently.

# Root Cause

The immediate root cause was that the beacon engine treated try_make_sync_target_canonical(...) as fire-and-forget in two consensus-related paths, so canonicalization failures could be ignored at the call site.

## Walkthrough

1. In on_new_payload(...), the pre-fix code called try_make_sync_target_canonical(block_num_hash) without handling its Result.

2. The patched on_new_payload(...) code wraps that call in an error check and examines whether the returned RethError::Canonical is fatal.

3. For fatal canonical errors, the patched code now returns BeaconOnNewPayloadError::Internal(Box::new(error)) instead of silently continuing.

4. In on_downloaded_block(...), the pre-fix code likewise called try_make_sync_target_canonical(downloaded_num_hash) and ignored any error.

5. The patched downloaded-block path now checks for Err((hash, error)) and logs an explicit unexpected-error message.

6. The added From<RethError> for InsertBlockErrorKind implementation is supporting error-plumbing code; the provided evidence does not show it as the root cause.

# Fix Pattern

Replace ignored Result values on canonicalization helpers with explicit error handling, and add error-conversion plumbing needed to propagate or report those failures.

## How It Was Fixed

The patch changed both beacon-engine call sites from unchecked try_make_sync_target_canonical(...) calls into explicit Err-handling branches. In the new-payload path, fatal canonicalization failures are now surfaced as an internal engine error. In the downloaded-block path, failures are at least logged. The error conversion change in blockchain_tree/error.rs supports carrying RethError values through shared error types.
