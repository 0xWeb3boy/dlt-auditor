## Before/After Behavior

Before the change, `is_fork` accepted only a target hash, there was no shown helper for scanning ancestors for missing trie updates, `get_canonical_blocks_to_persist` returned `Vec<ExecutedBlockWithTrieUpdates<N>>` directly, and the tree-state removal path assumed trie updates were present when removing canonical blocks. After the change, `is_fork` accepts a sealed header, a new `has_ancestors_with_missing_trie_updates` helper walks parent links and checks `block.trie.is_missing()`, `get_canonical_blocks_to_persist` becomes `&mut self -> Result<Vec<ExecutedBlockWithTrieUpdates<N>>, AdvancePersistenceError>`, and the removal path uses `removed.trie.take_present()` with an explicit skip when trie updates are absent.

# Root Cause

The prior logic appears to have assumed trie updates were already available along forked branches that later participate in canonical persistence, without an explicit ancestor check or a guarded handoff when trie data was missing.

## Walkthrough

1. `is_fork` changes from taking a hash to taking a sealed header, with a comment that this supports checking a block before it exists in tree state or the database.

2. A new helper, `has_ancestors_with_missing_trie_updates`, walks backward from the target block's parent through `tree_state.blocks_by_hash` and returns `true` if any ancestor has missing trie data.

3. `get_canonical_blocks_to_persist` changes from an infallible getter to a mutable method returning `Result<..., AdvancePersistenceError>`.

4. The updated method comment states that missing trie updates are handled by running state-root calculation and saving trie updates, and that failure in that calculation now surfaces as an error.

5. In `tree/state.rs`, removal of canonical blocks now calls `removed.trie.take_present()` and explicitly logs and skips the case where no trie updates are found.

# Fix Pattern

Add explicit missing-data detection and fallible handling at the persistence boundary instead of assuming derived state is always present.

## How It Was Fixed

The patch makes fork evaluation header-aware, introduces an ancestor scan for missing trie updates, changes canonical persistence batching to an error-returning path, and adds an explicit guard when removing canonical blocks if trie updates are absent.

# Why It Matters

1. The changed path controls what canonical state is prepared for persistence.

2. The fix replaces an implicit assumption about derived trie data with explicit checks.

3. The provided evidence supports data-integrity hardening, not a proven exploit or invalid-block acceptance bug.
