# Summary

The patch adds an explicit consistency check in block insertion so a block is rejected when its `parent_hash` matches a canonical block but the canonical height of that hash does not equal the claimed parent number. The evidence supports that this is a consensus-sensitive invariant check, but it does not establish a concrete vulnerability or exploit path.

2. In `crates/blockchain-tree/src/block_indices.rs`, the patch replaces `/// get canonical hash` with `/// Returns the block hash of the canonical block with the given number.`.

3. In `crates/blockchain-tree/src/blockchain_tree.rs`, the patch replaces `if Some(parent.hash) == self.block_indices.canonical_hash(parent.number) {` with `let canonical_parent_block = self.block_indices.canonical_hash(parent.number);`.

## Before/After Behavior

Before the patch, the visible canonical-parent check compared `parent.hash` against `canonical_hash(parent.number)`, and the provided diff does not show a reverse lookup from `parent_hash` back to a canonical number. After the patch, `BlockIndices::canonical_number` is added and `BlockchainTree::try_insert_block` rejects the block with `ConsensusError::ParentBlockNumberMismatch` when `block.parent_hash` is canonical at a different number than `parent.number`.

# Root Cause

The block admission path enforced only one direction of parent consistency in the shown code: number-to-hash lookup. The reverse condition, whether a canonical `parent_hash` also matched the claimed parent number, was not explicitly checked in the provided pre-patch path.

## Walkthrough

1. `try_insert_block` first handles the case where the parent is already tracked in a sidechain.

2. For canonical attachment, the code still checks whether the claimed parent hash equals the canonical hash at `parent.number`.

3. The patch adds `BlockIndices::canonical_number(block_hash)` to recover a canonical height from a canonical hash.

4. `try_insert_block` now calls that helper on `block.parent_hash`.

5. If the hash is canonical and the returned canonical number differs from `parent.number`, the function returns `ConsensusError::ParentBlockNumberMismatch`.

6. This turns the mismatch into an explicit rejection instead of letting later tree-processing continue.

# Fix Pattern

Add a reverse index lookup and enforce the missing consistency check at the block-admission boundary.

## How It Was Fixed

The change introduces `canonical_number` in `BlockIndices` and uses it in `BlockchainTree::try_insert_block` to detect canonical parent hash/number disagreement. On mismatch, the code now returns a consensus error rather than proceeding.

# Why It Matters

1. It makes parent-reference validation explicit instead of relying only on a forward lookup.

2. It prevents the tree logic from continuing with a block whose parent fields disagree with canonical indexing.

3. It strengthens a consensus-sensitive invariant, but the supplied evidence does not prove broader security impact.
