# Summary

The patch hardens Sui JSON-RPC `balanceChanges` construction by carrying object digests into the coin-fetching path and asserting that locally fetched coin objects match those digests before their contents are used. The evidence supports an RPC reporting integrity fix for stale or inconsistent local object reads. It does not establish a consensus bug, validator compromise, forged object acceptance, direct fund loss, or an attacker-controlled exploit path.

## Before/After Behavior

Before the patch, balance-change computation reduced object references to `(ObjectID, SequenceNumber)` and fetched coin objects from the local object provider without checking the fetched object's digest against the transaction effects or input refs. After the patch, the path carries optional `ObjectDigest` values, builds digest context from effects and owned or immutable input objects, and asserts that a fetched object's digest matches before parsing it for balance-change reporting.

# Root Cause

The balance-change reporting path treated object id and version as sufficient to trust a locally fetched coin object, even when the transaction effects or input refs contained digest identity material. This could allow RPC `balanceChanges` to be computed from local data that was inconsistent with the effects/input view, but the provided evidence does not prove this was exploitable as a security vulnerability.

## Walkthrough

1. `get_balance_changes_from_effect` processes successful transaction effects and gathers changed object references.

2. Before the patch, changed object refs were mapped down to object id and version, dropping the digest.

3. `fetch_coins` used only id and version to retrieve objects from `object_provider` and then parsed coin data if the object was a coin.

4. The patch preserves digests from changed object refs as `(id, version, Some(digest))`.

5. The patch also builds a digest map for immutable or owned input object refs and passes input-object context through RPC response paths when available.

6. `fetch_coins` now accepts optional digests and asserts that `o.digest()` equals the expected digest before continuing with coin parsing.

7. A digest mismatch now fails loudly instead of silently producing balance-change data from inconsistent local object data.

# Fix Pattern

Thread authenticated object identity material through derived RPC reporting code and validate local-store reads against it before using object contents for derived balance reporting.

## How It Was Fixed

`fetch_coins` was changed to accept optional object digests alongside object ids and versions. When a digest is present, it compares the expected digest to the fetched object's digest with `assert_eq!`. `get_balance_changes_from_effect` now preserves digests from changed object refs and collects input-object digests where available. RPC read and execution response paths were updated to make transaction input objects available for this balance-change computation.

# Why It Matters

1. Prevents silent RPC balance-change computation from a fetched coin object whose digest disagrees with effects or input refs.

2. Improves trust in derived balance reporting from JSON-RPC responses.

3. The fix is a hard failure on mismatch, not graceful recovery.

4. The evidence is limited to reporting integrity, not on-chain state correctness.

# Evidence Notes

Primary grounded evidence is the `balance_changes.rs` change from `(ObjectID, SequenceNumber)` to `(ObjectID, SequenceNumber, Option<ObjectDigest>)` and the added `assert_eq!(*digest, o.digest(), "Object digest mismatch--got bad data from object_provider?")`. Additional evidence shows digests being preserved from changed object refs, input-object digests being collected from `InputObjectKind::ImmOrOwnedMoveObject`, and RPC paths extracting or constructing transaction input context. Claims about consensus, validator logic changes, forged objects, double spends, direct theft, or balance mutation are unsupported by the supplied evidence. Protocol security invariant: RPC balance-change reporting should not compute coin balance changes from a locally fetched object when an expected object digest is available and the fetched object's digest differs from the effects or input-object reference.
