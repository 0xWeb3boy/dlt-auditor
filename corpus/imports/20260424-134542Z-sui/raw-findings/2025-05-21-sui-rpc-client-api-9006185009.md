## Before/After Behavior

Before the change, NodeConfig.policy_config was optional and absent unless operators supplied a policy-config block. The visible PolicyConfig default used NoOp spam and error policies. After the change, policy_config receives a serde default, traffic_control.rs defines a default DoS-oriented PolicyConfig using SocketAddr client identity and frequency-threshold policies, and authority_server.rs records x-forwarded-for hop counts in a new metric. The commit text states this is enabled in dry-run mode by default, so the supported behavior is observation/readiness rather than proven request blocking.

# Root Cause

The supported issue is an operational default gap: validator traffic-control policy_config was not populated unless operators manually configured it. The patch adds default policy configuration so the traffic-control path can be instantiated by default in dry-run mode. The evidence does not show that the prior behavior was exploitable, nor that the new default actively blocks malicious traffic.
