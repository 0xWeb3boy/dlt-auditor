# Summary

The patch is best characterized as SUI accounting hardening, not a proven vulnerability fix. The grounded evidence shows TemporaryStore::check_sui_conserved was adjusted to compute written-output SUI through TemporaryStore state instead of only the backing store, and supporting GetModule/ObjectStore trait implementations were added so that accounting code can resolve objects or modules through the needed storage abstractions. The commit message says this enables calling the conservation check after gas charging. The evidence does not prove an exploitable mint, burn, consensus failure, or attacker-controlled path.

## Before/After Behavior

Before the patch, the shown output-SUI calculation for written objects used get_total_sui(&self.store), anchoring lookup in the backing store. After the patch, it uses get_total_sui(&self), allowing the calculation to consult TemporaryStore behavior. The patch also adds GetModule implementations for TemporaryStore and AuthorityStore and ObjectStore implementations for InMemoryStorage to support this path. The exact execution_engine call site is not included in the provided evidence.

# Root Cause

The supported root cause is a state-visibility and ordering gap in the conservation-check plumbing: the SUI conservation logic needed to run after gas charging and use storage abstractions capable of seeing temporary written state. The evidence does not establish that this gap was exploitable.

## Walkthrough

1. TemporaryStore::check_sui_conserved reads gas_summary from gas_charged, tying the check to post-gas accounting.

2. The patch changes written-output SUI calculation from get_total_sui(&self.store) to get_total_sui(&self).

3. TemporaryStore gains GetModule and checks written package objects before falling back to underlying storage.

4. AuthorityStore gains GetModule by deserializing modules returned by its existing get_module path.

5. InMemoryStorage gains ObjectStore implementations for object lookup in in-memory contexts.

6. One storage-cost assertion is commented out with a TODO, so the patch is not a complete strengthening of every shown accounting check.

7. The supplied evidence supports security-relevant hardening of a ledger invariant but not a confirmed vulnerability.

# Fix Pattern

Run or enable invariant checking at the point where required gas/accounting state is available, and make the check resolve data through the execution-state abstraction rather than only persistent backing storage.

## How It Was Fixed

TemporaryStore::check_sui_conserved now passes &self into get_total_sui for written output objects. The patch adds trait implementations for TemporaryStore, AuthorityStore, and InMemoryStorage so the accounting path can resolve modules and objects through common abstractions needed by the conservation code.

# Why It Matters

1. SUI conservation is a core ledger accounting property.

2. Using stale backing-store state could weaken an invariant check.

3. The change improves validation coverage after gas charging.

4. Exploitability is not shown by the provided evidence.

5. Dynamic-field handling and the disabled assertion remain notable limits.
