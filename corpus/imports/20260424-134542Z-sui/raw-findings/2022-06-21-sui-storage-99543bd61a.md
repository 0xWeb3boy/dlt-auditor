# Summary

The patch fixes a missing rollback in Sui epoch finalization. Before the change, `finish_epoch_change` detected non-empty `checkpoints.extra_transactions` but only had a TODO for reverting them. After the change, it reverts each extra transaction through `AuthorityStore::revert_state_update` and clears the tracking set. This is likely security relevant because it enforces checkpoint finality against locally persisted non-finalized execution effects, but the provided evidence does not prove attacker control, theft, unauthorized signing, or observed network-wide divergence.

## Before/After Behavior

Before the patch, epoch finalization could encounter `checkpoints.extra_transactions` and perform no rollback in the supplied code path. After the patch, epoch finalization iterates over those extra transactions, calls `revert_state_update` for each transaction digest, and clears `extra_transactions` after rollback. The new helper is documented as deleting certificate/effects data, parent sync entries, new object states, and owner index changes for locally executed transactions that did not make the last checkpoint.

# Root Cause

The epoch finalization path recognized locally executed transactions that were not included in the last checkpoint, but the rollback was left as a TODO. That could leave durable authority-store artifacts for transactions that did not reach checkpoint finality.

## Walkthrough

1. `finish_epoch_change` runs while the validator is halted and verifies it is at the last checkpoint of the epoch.

2. The checkpoint state may contain `extra_transactions`. The supplied context shows this is checkpoint reconstruction state for transactions outside the checkpoint.

3. Before the fix, the code only checked whether `extra_transactions` was non-empty and did not revert anything in the provided hunk.

4. The patch loops over `checkpoints.extra_transactions` and calls `self.state.database.revert_state_update(&tx_digest.transaction)?` for each entry.

5. The added store helper is documented as reverting persisted execution artifacts for locally executed transactions that did not make the last checkpoint.

6. After rollback, `checkpoints.extra_transactions.clear()?` removes the bookkeeping entries.

# Fix Pattern

Replace detection-only handling of non-finalized epoch state with explicit rollback of each recorded extra transaction before completing epoch finalization.

## How It Was Fixed

The epoch reconfiguration code now calls a new authority-store rollback helper for every transaction in `checkpoints.extra_transactions`, then clears that set. The helper is documented as removing the transaction certificate and effects, parent sync entries for mutated objects, new object states, and owner index updates.

# Why It Matters

1. Preserves the checkpoint-finality boundary for durable validator state.

2. Prevents non-finalized local execution effects from surviving epoch finalization in this path.

3. Keeps checkpoint bookkeeping and authority-store state aligned.

4. The evidence does not establish a concrete exploit path or attacker capability.
