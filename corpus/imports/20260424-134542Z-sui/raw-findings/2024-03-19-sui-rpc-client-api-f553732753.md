## Before/After Behavior

Before the patch, the shown Anemo consensus RPC router applied `RequireAuthorizationLayer::new(AllowedPeers::new(...))` before adding the RPC service, with a TODO for metrics and additional filters. After the patch, `install_service` also computes the current committee epoch string and adds `RequireAuthorizationLayer::new(AllowedEpoch::new(epoch_string.clone()))`. The traced `AllowedEpoch` implementation rejects requests with a missing epoch header or a header that differs from the current epoch, returning `BadRequest`. Other commit changes add metrics, excessive-message-size reporting, and Quinn connection monitoring; the supplied evidence describes those as observability/support code rather than blocking security controls.

# Root Cause

# Fix Pattern

Add a request authorization/filter layer at the network routing boundary to validate protocol-context metadata before RPC dispatch.

## How It Was Fixed

The patch adds an `AllowedEpoch` authorization layer to the Anemo router after the existing `AllowedPeers` layer. `AllowedEpoch` requires an `epoch` request header and compares it with the node's current committee epoch, rejecting absent or mismatched values.
