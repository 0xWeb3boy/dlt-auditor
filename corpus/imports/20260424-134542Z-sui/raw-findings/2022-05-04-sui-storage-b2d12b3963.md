The supported finding is a likely gas-metering consistency fix. The clearest evidence is that `transaction_input_checker.rs::check_locks` now sums the gas-metered sizes of all checked input objects and calls `gas_status.charge_storage_read(total_size)?` before returning them. ## Before/After Behavior

Before the patch, the shown `check_locks` path enforced non-empty input objects and returned `Ok(all_objects)` without the displayed storage-read gas charge. After the patch, it charges storage-read gas based on `object_size_for_gas_metering()` for all returned objects. The gateway path also gained a preparatory step that reads input objects locally and fills missing objects from authority responses when available before execution continues.

# Root Cause

A transaction-input checking path could read and validate input objects without explicitly charging storage-read gas for those objects, creating inconsistent resource accounting between gateway-side processing and the authority-consistency goal described by the commit.

## Walkthrough

1. A transaction reaches gateway execution with declared input objects.

2. The gateway reads local input objects and prepares them for downstream checking or execution.

3. In the old shown `check_locks` behavior, lock errors and object arity were checked, then the collected objects were returned without the displayed storage-read charge.

4. The patch computes the total gas-metered size of all collected objects.

5. The patch calls `gas_status.charge_storage_read(total_size)?` before returning the objects.

6. The gateway path also attempts to synchronize missing input objects from authorities before execution, reducing divergence between local gateway state and authority-visible inputs.

# Fix Pattern

Add explicit gas charging at the transaction-input boundary and align gateway object preparation with authority-backed object availability.

## How It Was Fixed

The patch adds storage-read gas accounting in `sui_core/src/transaction_input_checker.rs::check_locks` by summing `object_size_for_gas_metering()` over all input objects and charging that total through `gas_status.charge_storage_read(total_size)?`. It also adds `sync_input_objects_with_authorities` in `sui_core/src/gateway_state.rs` and invokes it before gateway execution continues.

# Why It Matters

1. Gas metering is part of resource-exhaustion control in a blockchain transaction path.

2. Different gateway and authority accounting behavior can let one path undercharge work relative to another.

3. The evidence supports inconsistent storage-read accounting, not broader transaction forgery or consensus compromise.
