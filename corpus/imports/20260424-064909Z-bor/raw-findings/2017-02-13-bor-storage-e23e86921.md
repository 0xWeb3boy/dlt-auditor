# Summary

The strongest supported finding is a real integrity-check fix in the peer-facing chunk store path. Incoming chunk data is now hashed and compared with the advertised chunk key before acceptance, and related storage changes add fuller cleanup for already-corrupt local entries.

## Before/After Behavior

Before the patch, the store-request handler shown in `swarm/network/depo.go` could reach chunk update logic without first verifying that `req.SData` hashed to `req.Key`, and the already-local branch returned before any such check. After the patch, the handler hashes `req.SData`, compares it to `req.Key`, logs and ignores invalid chunks, and only then returns for local hits. Separately, `swarm/storage/dbstore.go` changes corrupt-entry handling from deleting only the data record and returning an error to using the store's fuller delete path, plus it adds cleanup support for existing bad entries.

# Root Cause

Incoming chunk payloads were not consistently validated against their content-addressed key in the peer-facing store path before being accepted into local chunk handling. A secondary storage issue was incomplete cleanup when a persisted chunk failed the same integrity check.

## Walkthrough

1. `Depo.HandleStoreRequestMsg` processes a peer-supplied `req.Key` and `req.SData`.

2. The old code returned immediately for an already-local chunk and, for other paths shown, proceeded toward updating the chunk without a hash-versus-key check.

3. The new code computes a hash over `req.SData` and compares it with `req.Key`.

4. If the hash does not match, the request is logged as invalid and ignored.

5. If the chunk was already local, the function now returns only after that validation step.

6. `DbStore.Get` still re-hashes stored bytes, but mismatch handling now uses the store's coordinated delete helper instead of deleting only the data entry.

7. `DbStore.Cleanup()` and the added `swarm cleandb` command provide repair support for corruption already present on disk.

# Fix Pattern

Add explicit content-address validation on untrusted ingress, then use coordinated deletion and cleanup tooling for previously persisted inconsistent state.

## How It Was Fixed

The patch inserts a payload-hash check in the network store-request path and rejects mismatched chunks before acceptance. It also changes dbstore corruption handling to use fuller record deletion and adds cleanup/repair code for existing corrupt entries.

# Why It Matters

1. Prevents acceptance of chunk payloads that do not match their advertised content key.

2. Closes a validation gap on a peer-facing input path.

3. Reduces the chance of leaving partial index/data corruption behind once a mismatch is detected.

4. Adds an operator-visible repair path for corruption that may already exist locally.
