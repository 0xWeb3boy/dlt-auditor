## Before/After Behavior

Before the patch, Prepare used `number % Sprint == 0` and appended validators from `snap.signers()` into `header.Extra`. After the patch, it uses `(number+1) % Sprint == 0`, fetches validators with `GetCurrentValidators(..., number+1)`, errors if they are unavailable, and sorts them by address. The shown verifyHeader hunk adds explicit checkpoint `Coinbase` and nonce checks. The shown verifyCascadingFields hunk now retrieves a snapshot before later validation, and snapshot now returns an error if recovery leaves `snap == nil`.

# Root Cause

The code appears to have had an under-specified checkpoint-boundary transition: validator data and validation prerequisites were not enforced as explicitly as they are after the patch. However, the evidence does not prove whether this was exploitable, consensus-breaking in practice, or primarily defensive cleanup.

## Walkthrough

1. `Prepare` no longer reuses `snap.signers()` under `number % Sprint == 0`; it switches to an explicit validator lookup for `(number+1) % Sprint == 0`.

2. The new `Prepare` path fails closed when `GetCurrentValidators` returns an error and sorts validators by address before encoding.

3. `verifyHeader` adds explicit checkpoint-only checks for zero beneficiary and the expected nonce values.

4. `verifyCascadingFields` now calls `snapshot(...)` and returns its error before continuing.

5. `snapshot` now explicitly errors if snapshot recovery results in `nil`.
