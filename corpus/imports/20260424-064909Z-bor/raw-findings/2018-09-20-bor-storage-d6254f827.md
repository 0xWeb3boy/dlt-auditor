# Summary

The evidence supports a chain-selection hardening change, not a state-corruption fix. In `core/blockchain.go`, equal-total-difficulty same-height forks were previously broken partly at random; the patch changes that path to prefer the locally mined block as canonical, with an explicit Clique exception due to deadlock risk. Added `isLocalFn` plumbing in `BlockChain`/`NewBlockChain` supports that policy, but the provided excerpts do not prove more than local reorg-policy hardening.

## Before/After Behavior

Before the patch, `WriteBlockWithState` handled equal-total-difficulty ties by block number and then random choice when heights matched: `mrand.Float64() < 0.5`. After the patch, the same location is rewritten into explicit branches, and the comment says same-difficulty ties should preferentially keep the locally mined block canonical. The same hunk also shows that Clique is exempted because preserving self-reorgs there can introduce deadlock. Separately, `BlockChain` gains an `isLocalFn func(common.Address) bool` field and `NewBlockChain(...)` gains a matching parameter, indicating new plumbing for local-miner awareness.

# Root Cause

The supported root cause is a weak equal-difficulty tie-break rule in canonical-head selection: same-height ties could trigger a random reorg instead of preserving the local node's freshly mined head. The patch also adds local-miner-awareness plumbing, which suggests the prior code lacked the context needed to express that preference cleanly.

# Fix Pattern

Replace probabilistic tie-breaking in a security-relevant reorg path with an explicit local-policy rule, and add the minimal identity/context plumbing needed to apply that rule while preserving engine-specific exceptions.

## How It Was Fixed

The patch changes equal-total-difficulty reorg handling in `WriteBlockWithState` from a random same-height tie-break to a policy described in code comments as preferring the locally mined block as canonical. It also extends `BlockChain` and `NewBlockChain` with an `isLocalFn` callback for local-miner awareness, and it explicitly exempts Clique because the stronger behavior can cause deadlock there. Test and benchmark constructor callsites were updated for the new signature.

# Why It Matters

1. It reduces unnecessary head churn during equal-difficulty fork races.

2. It hardens the exact control path the code already associates with selfish-mining resistance.

3. It is narrower than a validation fix: the evidence shows local tie-breaking policy, not acceptance of invalid blocks.

4. The Clique carve-out shows the change balances reorg resistance against liveness risk.
