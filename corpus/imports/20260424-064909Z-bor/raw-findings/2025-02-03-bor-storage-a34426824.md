## Before/After Behavior

Before the patch, the shown location in `core/headerchain.go` had a special-case comment about skipping reorg when inserted headers were already canonical. After the patch, the code explicitly calls `forker.ReorgNeeded(hc.CurrentHeader(), lastHeader)`, returns errors from that check, and returns early with `SideStatTy` when no reorg is needed. The tests were also rewritten from simple chain-shape setups to explicit fork-choice mocks that encode which inserts should be accepted or treated as side-chain cases.

# Root Cause

The evidence supports that an explicit fork-choice decision point in header import was removed or no longer enforced in the reverted change, and this patch restores that gate before treating imported headers as canonical progression.

## Walkthrough

1. `HeaderChain.writeHeadersAndSetHead` writes headers and prepares a result object.

2. The patched code now calls `forker.ReorgNeeded(hc.CurrentHeader(), lastHeader)` before proceeding.

3. If that call returns an error, the function now stops and returns the error.

4. If that call returns `false`, the function marks inserted headers as `SideStatTy` and returns without further promotion logic in the shown path.

5. Three tests in `core/forkchoice_test.go` were rewritten to use mocked fork-choice behavior for past, future, and overlapping chain inserts.

6. Those tests support that branch handling is now expected to depend on explicit fork-choice outcomes rather than insertion alone.

# Fix Pattern

Restore an explicit fork-choice gate at the canonical head transition point and add regression tests that encode allowed and disallowed branch-selection outcomes.

## How It Was Fixed

The patch reinstates `ForkChoice.ReorgNeeded` in `core/headerchain.go` and uses its result to classify imported headers as side-chain data when reorg is not warranted. The accompanying tests replace implicit chain-shape setups with mocked fork-choice predicates covering past, future, and overlapping inserts.

# Why It Matters

1. Canonical branch selection is consensus-sensitive logic.

2. Imported headers may be stored without necessarily becoming the winning branch.

3. An explicit gate reduces the chance that refactoring changes branch-selection behavior silently.

4. The evidence shows correctness hardening in fork-choice handling, but not a demonstrated exploit.
