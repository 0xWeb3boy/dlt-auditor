# Summary

The patch changes oracle slashing so abstentions count against a validator's valid-vote rate. Previously, `SlashAndResetCounters` computed the rate using only `MissCount`, allowing excessive abstentions to avoid the configured slash and jail consequences. After the patch, the formula subtracts `MissCount + AbstainCount`, and tests now expect bonded-token reduction and jailing when abstentions push participation below the threshold.

## Observed Patch Facts

1. In `x/oracle/keeper/slash_test.go`, the patch replaces `// no slashing for abstaining` with `// slashing for not voting validly sufficiently`.

2. In `x/oracle/keeper/slash_test.go`, the patch replaces `// Case 2.5, slash w/ no jail for abstaining` with `// Case 2.5, slash w/ jail for abstaining too much along with misses`.

3. In `x/oracle/keeper/slash.go`, the patch replaces `// Calculate valid vote rate; (SlashWindow - MissCounter)/SlashWindow` with `// Calculate valid vote rate; (SlashWindow - (MissCounter + AbstainCounter))/SlashWindow`.

4. In `x/oracle/abci_test.go`, the patch replaces `// because of implicit abstaining there shouldnt be slashing here` with `slashFraction := input.OracleKeeper.SlashFraction(input.Ctx)`.

## Before/After Behavior

Before the patch, abstentions did not reduce `validVoteRate`, and tests expected no slashing or jailing for an abstention-heavy case. After the patch, abstentions reduce `validVoteRate`; keeper and EndBlocker-level tests expect stake reduction by `slashFraction` and jailing where applicable.

# Root Cause

The oracle slashing calculation omitted `AbstainCount` from the valid-vote-rate numerator, so only missed votes were treated as invalid participation for threshold enforcement.

## Walkthrough

1. `SlashAndResetCounters` iterates validator vote penalty counters and computes `validVoteRate`.

2. Before the change, the formula used `votePeriodsPerWindow - votePenaltyCounter.MissCount`.

3. That excluded `votePenaltyCounter.AbstainCount`, so abstentions did not lower the rate used for slashing and jailing.

4. The patch changes the formula to `votePeriodsPerWindow - (votePenaltyCounter.MissCount + votePenaltyCounter.AbstainCount)`.

5. Keeper tests now expect an abstention-heavy validator to lose bonded tokens by the configured slash fraction and be jailed.

6. The EndBlocker-level test now expects implicit abstaining to lead to stake reduction rather than preserving the original bonded amount.

# Fix Pattern

Include all counted invalid oracle participation categories in the same slashing threshold calculation.

## How It Was Fixed

`x/oracle/keeper/slash.go` was updated so `validVoteRate` subtracts both missed and abstained vote counts. Tests in `x/oracle/keeper/slash_test.go` and `x/oracle/abci_test.go` were updated to assert slashing and jailing behavior for excessive abstention.

# Why It Matters

1. Validators can no longer avoid oracle participation penalties by abstaining instead of missing votes.

2. The slashing calculation now matches the threshold behavior asserted by the updated tests.

3. The supported impact is an economic enforcement bypass, not demonstrated price manipulation, production exploitation, chain halt, or consensus safety failure.
