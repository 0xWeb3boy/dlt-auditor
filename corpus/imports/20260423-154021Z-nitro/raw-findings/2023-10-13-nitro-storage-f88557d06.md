# Summary

The evidence supports a likely security fix for undercharging in the native/JIT Stylus activation path. The patch adds explicit gas-in/gas-out handling across the ArbOS-to-Rust activation boundary and burns the consumed amount afterward.

## Observed Patch Facts

1. In `arbitrator/jit/src/user/mod.rs`, the patch replaces `if out_hash_len != 32 {` with `let gas_left = &mut sp.read_u64_raw(gas);`.

2. In `arbos/programs/wasm.go`, the patch replaces `) (*wasmPricingInfo, common.Hash, error) {` with `) (common.Hash, u16, error) {`.

3. In `arbos/programs/wasm.go`, the patch replaces `func compileUserWasmRustWrapper(` with `func (vec *rustVec) intoSlice() []byte {`.

4. In `arbitrator/jit/src/gostack.rs`, the patch replaces `pub fn write_slice(&self, ptr: u64, src: &[u8]) {` with `pub fn write_slice<T: TryInto<u32>>(&self, ptr: T, src: &[u8]) {`.

## Before/After Behavior

Before the patch, the provided evidence does not show activation receiving a gas pointer, returning updated remaining gas, or burning activation cost on the ArbOS side. After the patch, `activate_wasm` reads a gas pointer, passes mutable gas into `native::activate(...)`, writes back the remaining gas, and zeroes outputs on error; `activateProgram` snapshots `burner.GasLeft()`, passes that budget into `activateWasmRustImpl(...)`, and burns the consumed delta.

# Root Cause

The activation interface between ArbOS Go code and the Rust/native/JIT implementation did not previously use the explicit gas-budget handoff and settlement flow shown in the patch, leaving activation work insufficiently integrated with normal gas accounting on the changed path.

## Walkthrough

1. `arbitrator/jit/src/user/mod.rs` now reads a `gas` pointer in the activation bridge in addition to the module-hash pointer.

2. The bridge creates `gas_left` from that pointer, passes it into `native::activate(...)`, and writes the updated value back after activation completes.

3. The activation error path now also writes `0` to the gas output and zeroes the module hash before returning an encoded error.

4. `arbos/programs/wasm.go` now snapshots `burner.GasLeft()` before calling the Rust activation entrypoint.

5. The Go side passes `&gas` into `activateWasmRustImpl(...)` and then burns the consumed amount based on the returned remaining gas.

6. `arbitrator/jit/src/gostack.rs` broadens `write_slice` pointer handling, but that looks like support plumbing for the bridge rather than the root issue.

# Fix Pattern

Thread a mutable gas budget through the cross-language activation call, return the remaining gas to the caller, and charge the consumed delta at the protocol burner layer.

## How It Was Fixed

The patch converts activation to a gas-aware interface. Rust/JIT activation now accepts and updates a mutable gas value, and ArbOS activation now supplies the current gas budget, receives the remaining gas back, and burns the difference. Error handling was also updated to write explicit gas and hash outputs.

# Why It Matters

1. Prevents activation work on the changed path from escaping normal gas charging.

2. Keeps ArbOS-side accounting aligned with native/JIT execution.

3. Reduces underpricing risk in a protocol resource-control path.
