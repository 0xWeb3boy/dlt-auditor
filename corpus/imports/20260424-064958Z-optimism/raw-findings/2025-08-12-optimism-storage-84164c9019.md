## Before/After Behavior

The patch also adds find_common_ancestor(), which derives an ancestor from the finalized safety head and is used by find_rewind_target(...) while walking backward to a canonical source block; the provided snippets do not show an equivalent finalized-anchor step in the before-state.

# Root Cause

The evidence points to incorrect or underspecified rewind-target selection in reorg handling, especially around activation-boundary cases. Without anchoring the search to finalized-derived state and then confirming canonical source history, the task could choose the wrong point to rewind to.

## Walkthrough

1. The reorg task entrypoint was rewritten to fetch the latest derivation state and drive reorg processing through find_rewind_target(...).

2. The updated find_rewind_target(...) first checks whether the latest source block is still canonical and returns no rewind target when it is.

3. If the latest source block is not canonical, the new code calls find_common_ancestor().

4. find_common_ancestor() reads the finalized safety head and maps it back to a source block with derived_to_source(...).

5. The reorg logic then walks backward through stored source blocks until it finds a canonical block and uses that block as the rewind target.

6. Tests were updated and a new activation-related case was added, which supports that the change targets reorg edge-case behavior rather than only instrumentation.

# Fix Pattern

Constrain reorg recovery with a finalized-state floor, then choose a rewind point only from canonical source history.

## How It Was Fixed

The patch introduced find_common_ancestor() to derive a lower bound from finalized state, changed find_rewind_target(...) to skip rewinds when the latest source is still canonical, and otherwise search backward until it finds a canonical source block. The tests were expanded to cover the activation-boundary scenario.

# Why It Matters

1. It reduces the chance of rewinding to a non-canonical or overly deep source block.

2. It helps keep derived state aligned with canonical L1 history during reorg edge cases.

3. The evidence supports a state-correctness and recovery fix, but not a proven exploit path.
