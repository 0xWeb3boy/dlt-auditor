# Summary

The patch fixes a signature-binding flaw in the snarkOS handshake path. Before the change, challenge responses signed and verified only the requester-provided nonce. After the change, the response creator generates a local response nonce, signs the requester nonce together with that local nonce, includes the local nonce in the response, and verifiers check the same combined byte string.

## Before/After Behavior

Before the patch, router challenge-response creation signed only `peer_request.nonce.to_le_bytes()`, and router/BFT gateway verification accepted a signature over only `expected_nonce.to_le_bytes()`. After the patch, response creation generates `response_nonce`, signs `[peer_request.nonce.to_le_bytes(), response_nonce.to_le_bytes()].concat()`, sends that nonce in `ChallengeResponse`, and both router and BFT gateway verification require the signature over `[expected_nonce.to_le_bytes(), nonce.to_le_bytes()].concat()`.

# Root Cause

The prior handshake response signature covered only the requester-provided nonce, so the signed payload was not bound to nonce material freshly generated by the signer during response creation.

## Walkthrough

1. A peer sends a challenge request containing a nonce.

2. Before the fix, the responder signed only that peer-provided nonce.

3. The verifier checked only the expected requester nonce, matching the old signed payload.

4. The patch adds a locally generated response nonce when creating a challenge response.

5. The signer now signs the requester nonce plus the locally generated response nonce.

6. The response schema carries the added nonce so the verifier can reconstruct the signed bytes.

7. Router and BFT gateway verification now reject responses unless the signature covers both nonce values.

# Fix Pattern

Bind handshake signatures to transcript data from both parties, carry the added signed field in the response schema, and verify the exact byte sequence produced by the signer.

## How It Was Fixed

`node/router/src/handshake.rs` now generates `response_nonce` in both initiator and responder response paths, signs the concatenation of the peer nonce and response nonce, and includes `nonce: response_nonce` in `ChallengeResponse`. `node/router/src/handshake.rs` and `node/bft/src/gateway.rs` now destructure that nonce and verify the signature over the combined nonce bytes. The router message and BFT event challenge-response structs now include the nonce field.

# Why It Matters

1. Prevents challenge responses from signing only counterparty-chosen data.

2. Improves binding between the response signature and the live handshake transcript.

3. Keeps router and BFT gateway challenge-response validation consistent.
