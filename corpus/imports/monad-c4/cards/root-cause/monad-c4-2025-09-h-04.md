## Violated Invariant

- Invariant: A block prepass must not let a later transaction authorization reclassify an earlier transaction unless the proposal path used the same ordered semantics.

## Trust Boundary

- Boundary: ordered transaction proposal -> block policy reserve accounting

## Attack Surface

- Entrypoint type: proposal sequencing and block-policy fee/reserve validation
- Sensitive sink: reserve-balance classification and block coherency acceptance

## Impact Pattern

- Primary impact: consensus-liveness
- Secondary impact: invalid-block-proposal
- Severity guide: high

## Short Reusable Lesson

- Txpool and block policy derived delegated status at different times. Txpool treated a sender as non-delegated until the authorization transaction appeared in order, while block policy collected all authorizations up front and applied delegated status to the entire block. Carry order information into block-policy accounting, such as whether delegation existed before the first transaction, or validate EIP-7702 delegated status using the same ordered transition model as proposal assembly.
