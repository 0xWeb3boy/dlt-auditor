## Violated Invariant

- Invariant: Every layer that validates an EIP-7702 authorization must agree whether a wrong-chain system-sender authorization is ignored as an invalid child or rejects the parent transaction/block.

## Trust Boundary

- Boundary: user transaction -> txpool admission -> block validation

## Attack Surface

- Entrypoint type: EIP-7702 transaction admission and block coherency validation
- Sensitive sink: consensus vote decision for proposed blocks

## Impact Pattern

- Primary impact: consensus-liveness
- Secondary impact: invalid-block-proposal
- Severity guide: high

## Short Reusable Lesson

- The same EIP-7702 authorization predicates existed in txpool and block validation, but their order changed the validity outcome. Txpool treated a wrong-chain authorization as skipped before seeing the forbidden system authority, while block validation saw the system authority first and rejected the whole block. Make EIP-7702 authorization validation order and failure disposition identical across txpool, block validation, block policy, and execution. In particular, reject or drop system-sender authorizations before chain-id skip logic if that is the block-validation rule.
