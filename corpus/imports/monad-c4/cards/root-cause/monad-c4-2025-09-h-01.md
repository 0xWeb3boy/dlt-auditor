## Missing Property

- Missing property: `type-specific-fee-accounting`

## Violated Invariant

- Invariant: Consensus block policy must reserve enough balance for the maximum gas cost that execution can charge for each transaction type; legacy and EIP-2930 transactions must not be capped by EIP-1559 effective-bid logic.

## Trust Boundary

- Boundary: user transaction -> txpool/block policy -> execution engine

## Attack Surface

- Entrypoint type: block-policy transaction affordability check
- Sensitive sink: block proposal acceptance and execution gas charging

## Impact Pattern

- Primary impact: consensus-liveness
- Secondary impact: fee-bypass
- Severity guide: high

## Short Reusable Lesson

- A shared max-gas-cost helper used one EIP-1559 formula for all transaction types. For legacy and EIP-2930 transactions, that helper capped the gas bid at base_fee + priority_fee, while execution charges the full gas_price. The result was a consensus-side affordability undercount. Branch by transaction type in the block-policy gas-cost helper: charge legacy and EIP-2930 transactions as gas_limit * gas_price, and use the EIP-1559 effective-bid formula only for dynamic-fee typed transactions. Add cross-layer tests against execution gas semantics.
