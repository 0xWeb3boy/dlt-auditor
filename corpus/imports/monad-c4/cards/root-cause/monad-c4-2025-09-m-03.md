## Missing Property

- Missing property: `pre-allocation-response-budgeting`

## Violated Invariant

- Invariant: RPC response size and batch budgets must be enforced before or during allocation/serialization, not only after every item and the aggregate wrapper have been materialized.

## Trust Boundary

- Boundary: unauthenticated RPC client -> JSON-RPC handler

## Attack Surface

- Entrypoint type: JSON-RPC batch and high-output method handler
- Sensitive sink: RPC process memory and serialization buffers

## Impact Pattern

- Primary impact: memory-exhaustion
- Secondary impact: rpc-denial-of-service
- Severity guide: medium

## Short Reusable Lesson

- The RPC path built every batch item, retained serialized per-item RawValue buffers, then serialized the whole response wrapper and only afterward enforced the response size cap. That made the cap too late to prevent peak memory pressure. Enforce per-item and aggregate budgets during response construction or streaming serialization, cap batch fanout and high-output endpoints, and avoid duplicating large RawValue buffers before checking size.
