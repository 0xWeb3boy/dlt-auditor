# Validation Card

## Metadata

- ID: `monad-c4-2025-09-h-02`
- Bug family: `input_validation_and_invariant_enforcement`
- Bug class: `cross-layer-predicate-order-mismatch`

## What Confirmed The Issue

- Evidence 1: The report identifies txpool and block-validator checks in opposite order.
- Evidence 2: The local contest code has txpool chain-id filtering before system-sender handling, while block validation checks the system sender first.
- Evidence 3: Current upstream txpool checks the recovered authority against the system sender before building a valid recovered authorization.

## What Could Have Invalidated It

- Compensating control 1: A single shared authorization validator is used by all layers.
- Compensating control 2: Different predicate order is harmless if every failure mode rejects the same parent object and cleans it from retry paths.

## Severity Guidance

- Expected impact band: consensus-liveness
- Expected severity band: high

## False-Positive Cautions

- Caution 1: No issue if all layers return the same parent-transaction validity result for every failing predicate
- Caution 2: No issue if txpool rejects the transaction before proposal or block validation only rejects the authorization side effect
- Caution 3: Impact is lower if invalid proposals are not retried and the offending transaction is evicted from hot pools
