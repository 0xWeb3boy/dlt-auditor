# Validation Card

## Metadata

- ID: `monad-c4-2025-09-m-04`
- Bug family: `input_validation_and_invariant_enforcement`
- Bug class: `block-device-trim-offset-miswrite`

## What Confirmed The Issue

- Evidence 1: The report identifies range[0] being advanced for trim and later reused as the pwrite offset for the preserved buffer.
- Evidence 2: Current upstream writes the preserved buffer at range[0] before advancing the range for BLKDISCARD.

## What Could Have Invalidated It

- Compensating control 1: The apparent offset mutation happens after pwrite or uses a separate original_offset for write-back.
- Compensating control 2: The path is never used for block devices or unaligned boundaries in deployed configurations.

## Severity Guidance

- Expected impact band: storage-corruption
- Expected severity band: medium

## False-Positive Cautions

- Caution 1: No issue if the preserved page is written before the discard range offset is advanced
- Caution 2: No issue if the original offset is stored separately and used for pwrite
- Caution 3: Impact is lower if only regular files use the code path and block devices are not supported in production
