# Validation Card

## Metadata

- ID: `monad-c4-2025-09-h-03`
- Bug family: `resource_accounting_and_limits`
- Bug class: `txpool-affordability-undercheck`

## What Confirmed The Issue

- Evidence 1: The report points to base-fee-only insert-time affordability and full-bid proposal validation.
- Evidence 2: The local contest txpool reads last_commit_base_fee around insertion while block policy computes max gas cost separately.
- Evidence 3: Current upstream txpool insertion compares account balance with compute_txn_max_gas_cost at the last committed base fee.

## What Could Have Invalidated It

- Compensating control 1: The txpool admission path already calls the full max-cost helper for the same transaction type.
- Compensating control 2: Later failure removes the transaction from tracked/hot scheduling before it can be selected again.

## Severity Guidance

- Expected impact band: txpool-denial-of-service
- Expected severity band: high

## False-Positive Cautions

- Caution 1: No issue if txpool insertion and forwarding use the same full-bid max-cost helper as proposal validation
- Caution 2: No issue if a later affordability failure evicts or demotes the transaction so it cannot starve proposals
- Caution 3: Impact is lower when pool capacity, per-sender limits, or rate limits prevent broad stuffing
