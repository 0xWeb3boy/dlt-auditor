# Validation Card

## Metadata

- ID: `monad-c4-2025-09-m-06`
- Bug family: `state_machine_and_lifecycle_consistency`
- Bug class: `stale-timer-coordinate-misrouting`

## What Confirmed The Issue

- Evidence 1: The report shows handle_vote_timer(round) extracting VoteReady(v) and calling send_vote_and_reset_timer(round, v).
- Evidence 2: The report traces leader selection and rescheduling from the passed round, not the vote round.
- Evidence 3: Current upstream logs a mismatch between vote_timer_round and v.round but calls send_vote_and_reset_timer(v).

## What Could Have Invalidated It

- Compensating control 1: The callback cannot observe a stored vote for a different round than the timer event.
- Compensating control 2: The send/reset helper derives all routing from the vote object and ignores stale timer coordinates.

## Severity Guidance

- Expected impact band: consensus-liveness
- Expected severity band: medium

## False-Positive Cautions

- Caution 1: No issue if the send helper only accepts the vote object and derives all routing from v.round
- Caution 2: No issue if stale timer callbacks are ignored or checked against the stored vote coordinate before side effects
- Caution 3: Impact is lower if duplicate vote routing to both current and next leaders is robust to coordinate drift
