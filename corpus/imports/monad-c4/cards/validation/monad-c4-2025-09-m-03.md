# Validation Card

## Metadata

- ID: `monad-c4-2025-09-m-03`
- Bug family: `resource_accounting_and_limits`
- Bug class: `post-serialization-response-size-check`

## What Confirmed The Issue

- Evidence 1: The report identifies join_all batch execution, Vec<Response> aggregation, per-item Box<RawValue>, final wrapper serialization, and late max_response_size enforcement.
- Evidence 2: The reported defaults allow 5000-request batches and a 25 MB response cap, which can still allocate far more than the cap before rejection.

## What Could Have Invalidated It

- Compensating control 1: The RPC framework counts bytes during serialization and stops before allocating the full response.
- Compensating control 2: Batch and endpoint limits make the worst-case memory footprint bounded below operational limits.

## Severity Guidance

- Expected impact band: memory-exhaustion
- Expected severity band: medium

## False-Positive Cautions

- Caution 1: No issue if response encoding streams with a byte budget and aborts before large buffers are allocated
- Caution 2: No issue if batch count, per-method result size, and aggregate result size are all capped before expensive work
- Caution 3: Impact is lower behind authentication, strict reverse-proxy limits, or low default batch sizes
