# Code-Shape Card

## Metadata

- ID: `monad-c4-2025-09-m-03`
- Bug family: `resource_accounting_and_limits`
- Bug class: `post-serialization-response-size-check`

## Code Shape Summary

- Short description of what the buggy code looked like: The RPC path built every batch item, retained serialized per-item RawValue buffers, then serialized the whole response wrapper and only afterward enforced the response size cap. That made the cap too late to prevent peak memory pressure.

## Search Motifs

- futures::future::join_all over an RPC batch before aggregate budget checks
- Vec<Response> holds many Box<RawValue> items
- serde_json::to_raw_value or equivalent serializes the whole wrapper after per-item serialization
- max_response_size check happens after result construction or final serialization
- high-output methods lack per-endpoint concurrency or byte budgeting

## Typical Asymmetry

- What was checked in one path but missing in another: futures::future::join_all over an RPC batch before aggregate budget checks

## Patch Pattern

- What the fix changed structurally: Enforce per-item and aggregate budgets during response construction or streaming serialization, cap batch fanout and high-output endpoints, and avoid duplicating large RawValue buffers before checking size.

## False Match Warnings

- No issue if response encoding streams with a byte budget and aborts before large buffers are allocated
- No issue if batch count, per-method result size, and aggregate result size are all capped before expensive work
- Impact is lower behind authentication, strict reverse-proxy limits, or low default batch sizes
