## Code Shape Summary

- Short description of what the buggy code looked like: A shared max-gas-cost helper used one EIP-1559 formula for all transaction types. For legacy and EIP-2930 transactions, that helper capped the gas bid at base_fee + priority_fee, while execution charges the full gas_price. The result was a consensus-side affordability undercount.

## Search Motifs

- compute_txn_max_gas_cost applies max_fee.min(base_fee + priority_fee) without branching on legacy/EIP-2930
- Rust block policy fee helper disagrees with C++ execution gas-price logic
- legacy transaction max cost is lower in proposal validation than in execution
- tests do not cover legacy gas_price above base_fee plus priority fee

## Typical Asymmetry

- What was checked in one path but missing in another: compute_txn_max_gas_cost applies max_fee.min(base_fee + priority_fee) without branching on legacy/EIP-2930

## Patch Pattern

- What the fix changed structurally: Branch by transaction type in the block-policy gas-cost helper: charge legacy and EIP-2930 transactions as gas_limit * gas_price, and use the EIP-1559 effective-bid formula only for dynamic-fee typed transactions. Add cross-layer tests against execution gas semantics.

## False Match Warnings

- No issue if legacy and EIP-2930 transactions use a separate full-gas-price branch before EIP-1559 math
- No issue if execution and block policy call the same type-aware helper or share conformance tests
- Impact is lower if invalid transactions are rejected or evicted before block proposal and cannot be repeatedly selected
