## Code Shape Summary

- Short description of what the buggy code looked like: A bounded queue was present, but the queue-full path panicked. The resource limit became a crash primitive because attacker-influenced bursts could force try_send to return an error that was unwrapped with expect.

## Search Motifs

- try_send(commands).expect in an executor reachable from network messages
- bounded mpsc channel capacity is treated as impossible to fill
- ForwardedTx or p2p batches multiply by connections before backpressure is applied
- queue-full, lagging, or closed-channel errors panic instead of dropping or slowing producers

## Typical Asymmetry

- What was checked in one path but missing in another: try_send(commands).expect in an executor reachable from network messages

## Patch Pattern

- What the fix changed structurally: Replace panic-on-full queue submission with explicit backpressure handling, bounded dropping, or recoverable error propagation; add tests that fill the command channel from attacker-like bursts.

## False Match Warnings

- No issue if queue-full is handled by returning an error, dropping low-priority work, or applying backpressure without panic
- No issue if the sender is only local/operator-controlled and cannot be influenced by peer traffic
- Impact is lower if supervisor restarts are safe and peer/rate limits make capacity exhaustion impractical
