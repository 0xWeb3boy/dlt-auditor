## Before/After Behavior

Before the patch, the scanner used `last_scanned`-style incremental behavior, returned a watermark, and skipped `(has_tee = true, has_zk = true, countered_index = 0)` by returning `None`. After the patch, each scan re-evaluates the full lookback window, no longer returns a new watermark, sets `scan_head` directly to the current end, and classifies the same dual-proof state as `Some(GameCategory::InvalidDualProposal)` for validation.

# Root Cause

The scanner treated candidate discovery as mostly one-time state keyed by a scan watermark even though game state can change after first observation, and it encoded a classifier rule that treated a dual-proof no-challenge state as ignorable.

## Walkthrough

1. `scanner.rs` documentation changed from scanning since `last_scanned` to re-evaluating the full lookback window on every call.

2. `scan()` changed from returning `(candidates, new_last_scanned)` to returning only `Vec<CandidateGame>`, matching removal of watermark tracking.

3. The error path stopped updating `lowest_error`, which was part of the old rollback/watermark model.

4. The classifier branch for `(true, true, 0)` changed from a skip with `None` to `Some(GameCategory::InvalidDualProposal)`.

5. New comments state that a second proof may be added via `verifyProposalProof` and that both proofs may still need validation.

6. Related context shows scanner output feeds later validation and dispute actions, so missed candidates would not reach those downstream paths.

# Fix Pattern

Replace incremental watermark-based discovery with stateless rescanning when tracked objects can mutate after first observation, and convert previously skipped mixed states into explicit actionable classifications.

## How It Was Fixed

The fix removed `last_scanned`-style scan progression from the scanner, made each tick rescan the entire configured lookback window, simplified metrics to report the current window end, and changed dual-proof no-challenge games from a skipped case to an explicit invalid proposal category that will be validated.

# Why It Matters

1. Mutable on-chain game state can change after first observation, so one-time discovery can miss later-relevant states.

2. A branch that returns `None` prevents downstream validation and dispute handling for that state.

3. The patch improves challenger coverage, but the provided evidence does not prove direct exploitability or protocol compromise.
