# Summary

The grounded change is that the EIP-8130 handler stopped blindly writing `nonce_sequence + 1` into the derived NonceManager slot and now reads the current slot value, compares it to the claimed sequence, and returns `NonceTooLow` or `NonceTooHigh` on mismatch. That establishes a real validation gap in this code path. What the provided evidence does not establish is whether mismatched nonce values could actually reach this handler in production without being rejected earlier, so the patch is security-relevant but not proven here as an exploitable vulnerability. The warm-nonce gas adjustment is supported as execution-time gas-accounting correctness, not as a demonstrated security issue.

## Before/After Behavior

Before the patch, the handler derived the nonce slot, constructed `new_nonce = U256::from(nonce_sequence + 1)`, and stored it without first loading or comparing the current slot value. After the patch, it `sload`s the current sequence, compares it to `U256::from(nonce_sequence)`, rejects mismatches with `NonceTooLow` or `NonceTooHigh`, and only then proceeds with the increment. Separately, execution gas now adjusts a cold worst-case intrinsic gas figure downward when the nonce key is warm.

# Root Cause

Missing read-compare-write validation in the EIP-8130 nonce update path: the handler trusted transaction-supplied `nonce_sequence` enough to derive and write the next stored value without first checking the authoritative stored sequence for that slot. The gas change is a separate accounting correction, not the root cause of the nonce issue.

## Walkthrough

1. The handler computes a nonce storage slot from `sender` and `nonce_key` and operates on `NONCE_MANAGER_ADDRESS`.

2. In the pre-change code shown, it prepares `new_nonce = U256::from(nonce_sequence + 1)` and writes it without a preceding `sload` of the current slot value.

3. The patched code first reads the current slot with `journal.sload(...).data` into `current_seq`.

4. It converts the transaction's claimed sequence to `expected = U256::from(nonce_sequence)` and compares `current_seq` with `expected`.

5. If they differ, it returns `InvalidTransaction::NonceTooLow` or `InvalidTransaction::NonceTooHigh` instead of overwriting the slot.

6. Only matching state now proceeds to the increment path.

7. A separate change recalculates effective intrinsic gas during execution by discounting the cold-warm nonce delta when the nonce key is warm; that supports gas correctness, not the nonce-validation thesis.

# Fix Pattern

Replace a blind state update driven by transaction input with a stateful read-compare-write check against the authoritative storage slot immediately before mutation. Keep gas estimation conservative before execution, then reconcile warm/cold costs once execution context is available.

## How It Was Fixed

The fix inserted an `sload` of the current NonceManager slot, compared it against the transaction's claimed `nonce_sequence`, and returned explicit nonce mismatch errors before performing the store. In the same commit, the handler also stopped charging the full cold-slot intrinsic gas during execution when the nonce slot was already warm, while leaving initial gas validation conservative.

# Why It Matters

1. It removes a blind overwrite pattern from a replay- and ordering-sensitive nonce path.

2. It makes nonce mismatches fail explicitly instead of silently advancing storage from transaction input.

3. It separates a potentially security-relevant nonce validation gap from a distinct gas-accounting correction.

4. It does not, from the provided evidence alone, prove exploitability or absence of upstream validation.
